# MTi 安装校准协议

本文档为从零实现 Xsens MTi 传感器 RotSensor 校准流程的开发者提供一份
独立的参考资料。

内容依次涵盖:

1. 与设备通信所需的 Xbus 帧格式。
2. 端到端的命令序列以及必须发送的精确字节。
3. 由一帧测量数据计算 `q_rotSensor` 所用的数学方法。
4. 校准工具内置的三种安装姿态预设及其预计算结果。
5. 一个完整的数值算例。

阅读本文档不需要参考任何源代码。

---

## 1. Xbus 帧格式

主机与 MTi 之间收发的每个字节都被封装为一个 Xbus 帧:

```
+----------+-----+-----+-----+---------+----------+
| 0xFA     | BID | MID | LEN | PAYLOAD | CHECKSUM |
+----------+-----+-----+-----+---------+----------+
  1 字节    1     1     1+    LEN 字节   1
```

| 字段     | 宽度         | 取值                                                    |
|----------|--------------|---------------------------------------------------------|
| 前导符   | 1 字节       | 固定为 `0xFA`                                           |
| BID      | 1 字节       | 总线 ID;串口通信使用 `0xFF`(主设备)                  |
| MID      | 1 字节       | 消息 ID(见 §3)                                        |
| LEN      | 1 或 3 字节  | 负载长度(见下文)                                      |
| PAYLOAD  | LEN 字节     | 因命令而异                                              |
| CHECKSUM | 1 字节       | 见下方公式                                              |

### 1.1 长度编码

如果负载长度小于 255 字节,LEN 为一个字节,直接表示长度。否则 LEN 为
三个字节: `0xFF` 后跟一个 16 位大端整数表示长度。本文涉及的全部命令负
载都很短(≤ 17 字节),因此 LEN 总是一个字节。

### 1.2 校验和

校验和的设置应使得从 BID 直到校验字节(含)的所有字节之和模 256 等
于 0:

```
checksum = (- (BID + MID + LEN + PAYLOAD[0] + ... + PAYLOAD[LEN-1])) & 0xFF
```

校验接收到的帧时,将 BID 到校验字节累加,结果必须 `≡ 0 (mod 256)`。

### 1.3 字节序

所有多字节整数字段均为**大端**。所有浮点数均为 IEEE-754 单精度(4 字
节),同样以**大端**存储。

### 1.4 应答约定

对每一条命令 MID,设备以 MID + 1 作为应答(例如 `0x30` GotoConfig →
`0x31` GotoConfigAck)。当请求失败时,设备返回 `XMID_Error = 0x42`,
负载中包含一个字节的错误码。

## 2. 端到端命令序列

校准过程分为三个阶段。下表给出的字节都是精确值:按所示内容(BID 取
主设备 `0xFF`,校验字节按 §1.2 计算)直接写到串口即可。

### 阶段 A — 准备设备

| #  | 方向       | 命令                                                         | 字节                                                              |
|----|------------|--------------------------------------------------------------|-------------------------------------------------------------------|
| 1  | 主机 → 设备 | GotoConfig (`0x30`)                                          | `FA FF 30 00 D1`                                                  |
| 2  | 设备 → 主机 | GotoConfigAck (`0x31`)                                       | `FA FF 31 00 D0`                                                  |
| 3  | 主机 → 设备 | SetAlignmentRotation,RotSensor = 单位四元数 (`0xEC`,frame=0)| `FA FF EC 11 00 3F 80 00 00 00 00 00 00 00 00 00 00 00 00 00 00 45` |
| 4  | 设备 → 主机 | SetAlignmentRotationAck (`0xED`)                             | `FA FF ED 00 14`                                                  |
| 5  | 主机 → 设备 | SetOutputConfiguration: Quaternion @ 100 Hz (`0xC0`)         | `FA FF C0 04 20 10 00 64 C9`                                      |
| 6  | 设备 → 主机 | OutputConfig 回显 (`0xC1`)                                   | 长度与内容随请求而变化;负载回显所请求的全部条目                  |
| 7  | 主机 → 设备 | GotoMeasurement (`0x10`)                                     | `FA FF 10 00 F1`                                                  |
| 8  | 设备 → 主机 | GotoMeasurementAck (`0x11`)                                  | `FA FF 11 00 F0`                                                  |

**说明**
- 步骤 3 — 单位四元数 `(w, x, y, z) = (1, 0, 0, 0)`,其 IEEE-754 单
  精度大端编码为 `3F 80 00 00 00 00 00 00 00 00 00 00 00 00 00 00`。
  LEN 之后的负载首字节为 *frame*: `0x00` = RotSensor。
- 步骤 5 — `SetOutputConfiguration` 的负载是一串
  `(XDI:u16-be, frequency:u16-be)` 二元组。`0x2010` 是 Quaternion 的
  XDI,`0x0064` 表示 100 Hz。可以扩展为多个二元组(每个 4 字节);此处
  示例只请求一个。

### 阶段 B — 采样

发送 GotoMeasurement 之后,设备开始按配置的频率以 MID `0x36` 的
MtData2 帧流式输出。主机需要:

1. **丢弃** GotoMeasurementAck 之后 `5000 ms` 内收到的所有帧。卡尔曼
   滤波器仍在收敛,姿态尚不可信。*在此期间传感器必须保持完全静止。*
2. 5000 ms 之后,取第一帧完整的 MtData2,从中提取四元数(XDI
   `0x2010`,12 字节数据段为 4 个大端 IEEE-754 浮点 `w, x, y, z`)。
   记为 `q_raw`。
3. 按 §4 由 `q_raw` 计算 `q_rotSensor`。

MtData2 的相关结构提示(仅列出此处用到的部分):

```
FA FF 36 LEN  XDI:u16-be  SIZE:u8  DATA...  ... 更多 (XDI, SIZE, DATA) ...  CHECKSUM
```

Quaternion 的 XDI 为 `0x2010`,`SIZE = 0x10`(16 字节 = 4 个大端浮
点)。

### 阶段 C — 持久化对准矩阵

| # | 方向       | 命令                                                         | 字节                                                            |
|---|------------|--------------------------------------------------------------|-----------------------------------------------------------------|
| 1 | 主机 → 设备 | GotoConfig (`0x30`)                                          | `FA FF 30 00 D1`                                                |
| 2 | 设备 → 主机 | GotoConfigAck (`0x31`)                                       | `FA FF 31 00 D0`                                                |
| 3 | 主机 → 设备 | SetAlignmentRotation,frame=0,负载 = `q_rotSensor`           | `FA FF EC 11 00 <w:4> <x:4> <y:4> <z:4> <chk>`                  |
| 4 | 设备 → 主机 | SetAlignmentRotationAck (`0xED`)                             | `FA FF ED 00 14`                                                |

步骤 4 之后,设备已将新的对准矩阵保存到非易失存储器,后续上电会自动
应用。

## 3. 消息参考

本协议中用到的命令汇总:

| MID  | 名称                       | 方向          | 应答               |
|------|----------------------------|---------------|--------------------|
| 0x10 | GotoMeasurement            | 主机 → 设备   | 0x11               |
| 0x30 | GotoConfig                 | 主机 → 设备   | 0x31               |
| 0x36 | MtData2                    | 设备 → 主机   | (无应答)           |
| 0x42 | Error                      | 设备 → 主机   | (无应答)           |
| 0xC0 | SetOutputConfiguration     | 主机 → 设备   | 0xC1 OutputConfig  |
| 0xEC | SetAlignmentRotation       | 主机 → 设备   | 0xED               |

所有携带负载的 MID 都遵循 "应答 MID = 请求 MID + 1" 的约定。当设备
无法满足请求时,会以 Error 消息 (`0x42`) **替代**预期应答。

## 4. 计算 `q_rotSensor`

### 4.1 本文使用的四元数约定

`q = (w, x, y, z)`,其中 `w` 为标量部分。

- **乘法**(Hamilton 积)。`r = a ⊗ b`:
  ```
  r.w = a.w·b.w − a.x·b.x − a.y·b.y − a.z·b.z
  r.x = a.x·b.w + a.w·b.x − a.z·b.y + a.y·b.z
  r.y = a.y·b.w + a.z·b.x + a.w·b.y − a.x·b.z
  r.z = a.z·b.w − a.y·b.x + a.x·b.y + a.w·b.z
  ```
- **单位四元数的共轭 / 逆**:
  `q* = (w, −x, −y, −z)`。
- **绕轴-角的构造**(绕某轴旋转 `θ` 弧度):
  ```
  q_x(θ) = (cos(θ/2), sin(θ/2), 0, 0)
  q_y(θ) = (cos(θ/2), 0, sin(θ/2), 0)
  q_z(θ) = (cos(θ/2), 0, 0, sin(θ/2))
  ```
- **Tait-Bryan ZYX 欧拉角提取**(以度为单位),输入须为单位四元数:
  ```
  sinr = 2(w·x + y·z)
  cosr = 1 − 2(x² + y²)
  roll(滚转)  = atan2(sinr, cosr) · 180/π

  sinp = 2(w·y − z·x)               (在调用 asin 之前限制到 [−1, 1])
  pitch(俯仰) = asin(sinp) · 180/π

  siny = 2(w·z + x·y)
  cosy = 1 − 2(y² + z²)
  yaw(偏航)   = atan2(siny, cosy) · 180/π
  ```

### 4.2 构造安装四元数

一个安装预设是一个有序的 `(轴, 度数)` 列表,以**外旋**方式依次应用。
通过组合各轴四元数构造 `q_mount`,每一步都**左乘**:

```
q_mount ← (1, 0, 0, 0)
for (axis_i, deg_i) 按顺序遍历预设:
    q_step ← 由 axis_i 和 deg_i 构造的轴四元数
    q_mount ← q_step ⊗ q_mount         # 左乘
return q_mount
```

### 4.3 估计自然坐标系下的姿态

原始四元数 `q_raw` 表示传感器静止时的实际姿态,其中已包含安装方向。
通过抵消安装方向,估计传感器若处于自然姿态时的方向:

```
q_unmount = conjugate(q_mount)
q_natural = q_raw ⊗ q_unmount
```

按 §4.1 将 `q_natural` 转换为欧拉角。其中的偏航分量记为
`yaw_natural`(以度为单位)。

如果传感器确实水平且预设与实际安装相符,`q_natural` 的滚转和俯仰应当
接近 0。若残差较大,则说明地面不平或所选预设不对。

### 4.4 构造目标姿态

校正后的传感器输出应为**滚转 0、俯仰 0,偏航等于自然坐标系下的偏航**。
将其表示为纯偏航四元数:

```
q_target = (cos(yaw_natural · π / 360),
            0,
            0,
            sin(yaw_natural · π / 360))
```

(除以 360 是将"半角"与"角度转弧度"合并: `deg · π / 360 =
(deg/2) · π / 180`。)

### 4.5 求解 `q_rotSensor`

设备应用校正的方式为 `q_corrected = q_raw ⊗ q_rotSensor`。令
`q_corrected = q_target` 求解可得:

```
q_rotSensor = conjugate(q_raw) ⊗ q_target
```

将这四个浮点数作为 SetAlignmentRotation 命令的负载写入设备,frame =
`0x00` (RotSensor)。完整帧格式见 §2 阶段 C。

## 5. 三种预定义安装姿态

校准工具内置三种预设。下表列出每个预设的旋转序列以及由此得到的
`q_mount`。

| 预设 | 旋转步骤(外旋)         | `q_mount` `(w, x, y, z)`                        |
|------|--------------------------|-------------------------------------------------|
| 1    | z = +90°,接着 y = +180° | `(0.0000000, 0.7071068, 0.7071068, 0.0000000)`  |
| 2    | z = +180°,接着 y = +90° | `(0.0000000, 0.7071068, 0.0000000, 0.7071068)`  |
| 3    | y = −90°                 | `(0.7071068, 0.0000000, −0.7071068, 0.0000000)` |

每个预设的 `q_rotSensor` **不是**固定值——它由运行时实测得到的
`q_raw` 决定,详见 §4.5 与 §6 的算例。

以预设 1 为例手工推导 `q_mount`:

```
q_step₁ = q_z(+90°) = (cos45°, 0, 0, sin45°) = (0.7071068, 0, 0, 0.7071068)
q_mount = q_step₁ ⊗ (1, 0, 0, 0) = (0.7071068, 0, 0, 0.7071068)

q_step₂ = q_y(+180°) = (cos90°, 0, sin90°, 0) = (0, 0, 1, 0)
q_mount = q_step₂ ⊗ q_mount

       w =  0·0.7071 − 0·0 − 1·0 − 0·0.7071     = 0
       x =  0·0.7071 + 0·0 − 0·0 + 1·0.7071     = 0.7071068
       y =  1·0.7071 + 0·0 + 0·0 − 0·0.7071     = 0.7071068
       z =  0·0.7071 − 1·0 + 0·0 + 0·0.7071     = 0
       q_mount = (0, 0.7071068, 0.7071068, 0)
```

预设 2、3 完全适用同一方法。

## 6. 算例(预设 1,理想情形)

假定传感器严格按预设 1(z=+90°,y=+180°)安装在水平地面上。设备在
静止时报告的原始四元数恰好等于安装四元数本身:

```
q_raw = q_mount = (0, 0.7071068, 0.7071068, 0)
```

### 第 1 步 — 抵消安装

```
q_unmount = conjugate(q_mount) = (0, −0.7071068, −0.7071068, 0)
```

### 第 2 步 — 自然坐标系估计

```
q_natural = q_raw ⊗ q_unmount = q_mount ⊗ conjugate(q_mount) = (1, 0, 0, 0)
```

这是单位四元数——滚转、俯仰、偏航全为 0。真实采样会有一定残差,但算
法本身可以容纳这些残差。

### 第 3 步 — 自然坐标系下的欧拉角

```
yaw_natural = 0°
```

### 第 4 步 — 目标

```
q_target = (cos 0°, 0, 0, sin 0°) = (1, 0, 0, 0)
```

### 第 5 步 — 求解

```
q_rotSensor = conjugate(q_raw) ⊗ q_target
            = (0, −0.7071068, −0.7071068, 0) ⊗ (1, 0, 0, 0)
            = (0, −0.7071068, −0.7071068, 0)
```

### 第 6 步 — SetAlignmentRotation 写入的字节

下面用到的常数及其 IEEE-754 单精度大端编码:

| 浮点值      | 字节        |
|-------------|-------------|
| `+1.0`      | `3F 80 00 00` |
| `0.0`       | `00 00 00 00` |
| `+0.7071068`| `3F 35 04 F3` |
| `−0.7071068`| `BF 35 04 F3` |

**RotSensor 帧**(frame 字节 = `0x00`,负载 =
`q_rotSensor = (0, −0.7071068, −0.7071068, 0)`):

```
FA FF EC 11 00 00 00 00 00 BF 35 04 F3 BF 35 04 F3 00 00 00 00 2E
```

校验和推导(从 BID 到最后一个负载字节累加后取负,再模 256):

```
sum = 0xFF + 0xEC + 0x11 + 0x00 + 0x00 + 0x00 + 0x00 + 0x00
    + 0xBF + 0x35 + 0x04 + 0xF3 + 0xBF + 0x35 + 0x04 + 0xF3
    + 0x00 + 0x00 + 0x00 + 0x00
    = 1490 = 0x5D2
sum mod 256 = 0xD2
checksum    = (256 − 0xD2) mod 256 = 0x2E
```

该帧按 §2 阶段 C 描述的 SetAlignmentRotationAck 路径处理。

## 8. 错误处理

- 如果在任何阶段设备返回 `0x42` (Error) 而非预期的应答,应立即中止,
  并将负载中的一字节错误码上报。
- 如果在单条命令的超时时间内没有收到应答,中止操作。常见原因:设备
  未处于测量模式(对 `0xC0` 而言)、波特率错误,或电缆断开。
- 如果某帧的校验和(§1.2)不匹配,丢弃该帧并继续解析后续字节流——不
  要中止。
- 阶段 B 的预热期间传感器**必须保持静止**。运动会污染 `q_raw`,导致
  `q_rotSensor` 计算错误。如果怀疑传感器在此期间移动过,应重做校准。
